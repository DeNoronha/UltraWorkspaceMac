# Teams bar app: what "Flow for Outlook & Teams" does and how Deckhand could offer it

Research note, 4 November 2026. No code was changed. The question: what does the Elgato Marketplace plugin "Flow for Outlook & Teams" do, and what would a Deckhand bar app (1424×280 page on the UltraBar X) need to offer the same on macOS? The short version: the plugin is a Microsoft Graph client (mail, calendar, presence) with no in-call controls at all; for Deckhand most of it can be done with no sign-in from Apple Calendar and Apple Mail, and only Teams presence (read and set) needs an Entra app registration and Microsoft Graph. In-call controls (mute, camera, raise hand) are not possible any more on macOS: Microsoft retired the Teams desktop client's third-party control API on 30 June 2026.

## 1. What the plugin is and does

Two listings exist under this name, both by FlowKits (Microsoft Verified Publisher, domain getflowkits.com; not David Soulier or "Flow" the company). The URL in the question, [Flow for Outlook and Teams (Edge)](https://marketplace.elgato.com/product/flow-for-outlook-and-teams-edge-c74d939d-a9ef-42d1-91d7-63d23e275a8f), is the **iCUE widget for the Corsair XENEON EDGE** touch screen (Windows only, $15, version 1.1.1 of 30 October 2026, needs a Windows companion app). The Stream Deck plugin is [Flow for Outlook & Teams](https://marketplace.elgato.com/product/flow-for-outlook-teams-da431b4f-b46a-4bfa-bfb5-f43c6e909a62) (Windows and macOS, Stream Deck 7.1+, version 1.4 of 21 October 2026, 27 key and dial actions). Both share one Entra app registration (client id `2e0afd52-abb3-4d7f-833d-4f804eb982d6`) and talk only to `graph.microsoft.com`; FlowKits runs no server. Setup guides: [Stream Deck](https://getflowkits.com/setup/microsoft-outlook-teams-stream-deck/), [Edge companion](https://getflowkits.com/setup-companion/outlook-teams/), [IT approval page](https://getflowkits.com/it-approval/outlook-teams).

What the two products show and do, merged (the Edge widget is the richer, panel-shaped one and the closest analogue of a bar page):

| Feature | Stream Deck plugin | XENEON EDGE widget | Where the data comes from |
|---|---|---|---|
| Teams presence: show own status | Yes (Status key, colour) | Yes | Graph `GET /me/presence` (Presence.Read) |
| Set presence: Available, Busy, Do not disturb, Be right back, Away, Appear offline | Yes, one tap cycles or Quick Status sets one | Yes | Graph `setUserPreferredPresence` (Presence.ReadWrite) |
| Focus timer: DND for 25 min to 2 h, then restore | Yes | Yes | Same, with `expirationDuration` |
| Teams status message key | Yes (v1.4 note) | — | Graph `setStatusMessage` |
| Next meeting with countdown, join on the same key | Yes | Yes ("joins that meeting and not a different one") | Graph `calendarView`, event `onlineMeeting.joinUrl` |
| Agenda (dial browse; today / 7 days / month grid) | Dial | Grid views | Graph calendar |
| Create instant meeting | Yes | — | Graph OnlineMeetings.ReadWrite |
| Date & week key with weekly meeting count | Yes (v1.4) | — | Graph calendar |
| Unread mail count, inbox/sender/search monitors, latest sender and subject | Yes | Inbox list, newest first, per-account counts | Graph Mail.ReadWrite (read; mark read is the only write) |
| Mark latest message or folder read; open mail, folder or compose in Outlook on the web | Yes (opens Outlook web) | Tap opens, press-and-hold marks read | Graph + browser |
| Teams chats: unread chat count, send preset message to person/channel | Yes | Chat list page | Graph Chat.Read, ChannelMessage.Send |
| Mute, camera, raise hand, leave, reactions during a call | **No** | **No** | — |
| Multiple accounts, privacy mode, themes, layouts | Partly (themes) | Yes | Local |

Delegated Graph scopes the registration asks for (from the IT approval page): `Mail.ReadWrite`, `Calendars.Read`, `Presence.Read`, `Presence.ReadWrite`, `Chat.Read`, `Chat.ReadWrite`, `ChannelMessage.Send`, `Team.ReadBasic.All`, `Channel.ReadBasic.All`, `OnlineMeetings.ReadWrite`, `User.Read`, plus `openid profile offline_access`. No application permissions. Sign-in is the Microsoft page in the browser; tokens are encrypted with the OS key store (DPAPI on Windows, Keychain on macOS) and held in memory otherwise; crash reports go to Sentry. Work accounts "may need IT admin approval" (the page has a one-click admin consent link and the "Assignment required" tip). Personal Microsoft accounts get mail and calendar only, because Graph presence is not supported for personal accounts.

**Which features use the Teams local API versus Graph:** none of FlowKits' features use the Teams desktop client's local "third-party app API"; everything is Microsoft Graph in the cloud. The local API (a websocket on localhost, enabled in Teams under Settings → Privacy → Third-party app API → Manage API, with an API token in the classic client and an Allow/Block prompt during a meeting in the new client, per Microsoft's [Connect to third-party devices in Microsoft Teams](https://support.microsoft.com/en-US/teams/calls-devices/connect-to-third-party-devices-in-microsoft-teams)) was what the **official Microsoft Teams Stream Deck plugin** used for mute, camera, raise/lower hand, reactions, leave and background blur. That plugin's listing now returns 404 on the Marketplace. Microsoft message centre post [MC1266901](https://mc.merill.net/message/MC1266901) (published 31 March 2026) retired this "legacy external Teams meeting controls integration capability" in the Teams desktop client on **Windows and Mac on 30 June 2026** and removed the Settings → Privacy option; "this change does not affect supported Microsoft Teams integration models or published Microsoft Graph APIs", and no replacement is named. Secondary coverage: [Windows Report](https://windowsreport.com/microsoft-to-retire-legacy-teams-meeting-controls-on-windows-and-macos/), [Microsoft Q&A thread](https://learn.microsoft.com/en-us/answers/questions/5866166/retirement-of-legacy-third-party-meeting-and-call) (a moderator confirms there is no documented way to find affected tools). So the split is: presence, calendar, mail, chats = Graph; in-call controls = the retired local API, and nothing else.

## 2. What each feature needs on macOS, in two tiers

New input from the user changes the picture: the Outlook/Exchange mailbox is also set up in Apple Mail, and the Exchange calendars are in Apple Calendar. Deckhand already reads Apple Calendar through EventKit (`Sources/UltraWorkspaceApp/Widgets/CalendarSource.swift`, used by the Calendar app and cube card; the app declares `NSCalendarsFullAccessUsageDescription` in `packaging/Info.plist`) and already drives Apple Music through AppleScript (`Sources/UltraWorkspaceApp/Integrations/AppleMusic.swift`, `NSAppleEventsUsageDescription` declared). So the bar app splits into a tier that needs **no sign-in at all** and a tier that needs an **Entra app registration**.

### Tier 1: no sign-in needed (local sources)

**Next meeting, countdown, today's remaining meetings.** `CalendarSource.upcoming` already returns title, start, end, all-day flag and calendar colour from `EKEventStore`. For the Teams page it needs three more fields per event, all on `EKEvent` already: `organizer?.name` (an `EKParticipant`), `location`, `notes` and `url`. Restrict to the Exchange calendars (the existing `calendarIDs` setting, or filter on `calendar.source.sourceType == .exchange`) so personal iCloud calendars stay off the work page. Skip events whose `availability == .free` and all-day events by default, as FlowKits does.

**Teams join link.** Exchange delivers the Teams meeting as the event body; via EWS sync Apple Calendar keeps that body in `notes` (plain text with the link), Calendar.app's own "Join" button is built from exactly that detection, and some invites also carry the link in `location` or in the `url` field. No Apple document pins down the field, and community reports differ (Zoom links land in Notes per [MacRumors](https://forums.macrumors.com/threads/any-way-to-insert-zoom-or-teams-meetings-directly-into-apple-calendar-os-x.2326402); some Teams invites show the URL in Notes, others a blank Notes area per [Apple Support Communities](https://discussions.apple.com/thread/255783988); Apple's own "Join" detection is described on the [Apple Developer Forums](https://developer.apple.com/forums/thread/747159)). So extract defensively: concatenate `url?.absoluteString`, `location` and `notes`, and take the first match of `https://teams\.microsoft\.com/l/meetup-join/[^\s<>"')]+` (also accept `https://teams\.live\.com/meet/[^\s<>"')]+` for personal-account meetings and `https://[a-z0-9.-]*\.?zoom\.us/j/[^\s<>"')]+` if Zoom should get a Join button too). Teams deep links must start with `https://teams.microsoft.com/l/` per [Configure deep links](https://learn.microsoft.com/microsoftteams/platform/concepts/build-and-test/deep-links#protocol-handlers-in-deep-links); the `msteams://` scheme "skips the client selection screen in the browser and opens the deep link directly in the Teams desktop client", so to open the meeting on the Mac replace the `https://` prefix with `msteams://` when Teams is installed (`NSWorkspace.shared.urlForApplication(toOpen: URL(string: "msteams://")!) != nil`) and fall back to the `https://` link otherwise. **To verify on this Mac before building:** open one real Teams invite in Calendar.app, Export it as .ics, and check which of DESCRIPTION, LOCATION and URL carries the `meetup-join` link; or add a one-line debug print of `notes`/`url`/`location` in `CalendarSource`. There is already a `People.teamsChat` in `Sources/UltraWorkspaceApp/Integrations/People.swift` that opens `https://teams.microsoft.com/l/chat/0/0?users=…`, so the open-a-Teams-link path exists.

**Unread mail count.** Apple Mail exposes it over Apple Events. `tell application "Mail" to get unread count of inbox` returns the unified inbox count across all accounts; for only the Exchange account use `tell application "Mail" to get unread count of mailbox "INBOX" of account "<account name>"` (the account name as shown in Mail → Settings → Accounts; list them with `name of every account`). The slower `count of (messages of inbox whose read status is false)` also works but walks every message; prefer the `unread count` property. Run it through the same `NSAppleScript` helper as `AppleMusic.run`, on a utility task, no more than every 30–60 s. Caveats: the first call triggers the macOS Automation prompt "Deckhand wants to control Mail" (error -1743 until granted; the grant is per host app, under System Settings → Privacy & Security → Automation; see the [Apple Developer Forums thread](https://developer.apple.com/forums/thread/108815)); if Mail is not running, the Apple Event launches it, so either accept that or check `NSRunningApplication.runningApplications(withBundleIdentifier: "com.apple.mail")` first and show "Mail not open"; the count is whatever Mail has synced, which lags Exchange by Mail's fetch interval. A tap on the mail block can `open -a Mail` or `open "message://"`; opening Outlook on the web like FlowKits does is also possible with `https://outlook.office.com/mail/`.

Everything in this tier is built from code paths Deckhand already has (EventKit, AppleScript, the `/<page>/data.json` feed and the `X-Deckhand: action` POST routes in `BarPages.swift`), needs no network account, no token, no consent and no polling limits.

### Tier 2: Entra app registration + Microsoft Graph (presence only)

**Read own presence.** `GET https://graph.microsoft.com/v1.0/me/presence` with delegated `Presence.Read` ([Get presence](https://learn.microsoft.com/graph/api/presence-get?view=graph-rest-1.0)). Returns `availability` (`Available`, `Away`, `BeRightBack`, `Busy`, `DoNotDisturb`, `Focusing`, `InACall`, `InAMeeting`, `Offline`, `Presenting`, `PresenceUnknown`), `activity`, `statusMessage`, `outOfOfficeSettings` and `workLocation` ([presence resource](https://learn.microsoft.com/graph/api/resources/presence?view=graph-rest-1.0#properties)). Note that `InACall`, `InAMeeting` and `Presenting` arrive here automatically from the Teams client, which gives the bar a passive "in a call" indicator without any local API. Not supported for personal Microsoft accounts. Rate limit: 1,500 requests per 30 s per app per tenant for this call, 10,000 per 30 s for presence overall ([throttling limits](https://learn.microsoft.com/graph/throttling-limits#cloud-communication-service-limits)); polling every 10 s while the page is open (and every 60 s otherwise, like the flights feed) is far below that. Change notifications for presence exist but need a public HTTPS webhook, so a desktop app without a server polls.

**Set own presence.** `POST /me/presence/setUserPreferredPresence` with `{ "availability": "DoNotDisturb", "activity": "DoNotDisturb", "expirationDuration": "PT1H" }`, delegated `Presence.ReadWrite` ([setUserPreferredPresence](https://learn.microsoft.com/graph/api/presence-setuserpreferredpresence?view=graph-rest-1.0)). Supported pairs: Available/Available, Busy/Busy, DoNotDisturb/DoNotDisturb, BeRightBack/BeRightBack, Away/Away, Offline/OffWork. Default expiry when omitted: 1 day for Busy and DoNotDisturb, 7 days for the rest. This is the same "preferred presence" the Teams client sets when the user picks a status in the Teams menu, so it shows in Teams immediately and the user can override it there. `POST /me/presence/clearUserPreferredPresence` returns to automatic. The preferred presence "takes effect only when at least one presence session exists" (that is, Teams is signed in somewhere), otherwise the user shows Offline. `POST /me/presence/setStatusMessage` sets the text message with an optional expiry ([setStatusMessage](https://learn.microsoft.com/graph/api/presence-setstatusmessage?view=graph-rest-1.0)). The other action, `setPresence`, creates an app-owned presence session (5 min to 4 h) and is meant for apps reporting "InACall" and the like; it is not what a status cycle wants.

**Auth flow for a desktop app with no server.** Two fits, both "public client" (no secret):

- *Device code flow* ([OAuth 2.0 device authorization grant](https://learn.microsoft.com/entra/identity-platform/v2-oauth2-device-code)): Deckhand POSTs to `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/devicecode` with `client_id` and `scope=Presence.Read Presence.ReadWrite offline_access openid profile`, gets `user_code`, `verification_uri` (`https://microsoft.com/devicelogin`), `device_code`, `interval` and 15 min `expires_in`; shows the code in Apps → Teams (and can show it on the bar page too); polls `/oauth2/v2.0/token` with `grant_type=urn:ietf:params:oauth:grant-type:device_code` every `interval` seconds until it gets `access_token` + `refresh_token`. It needs "Allow public client flows: Yes" on the registration and no redirect URI. MSAL for iOS/macOS does **not** implement device code (Microsoft's desktop guidance says "this flow doesn't apply to macOS" for that library, [Acquire a token using device code flow](https://learn.microsoft.com/entra/identity-platform/scenario-desktop-acquire-token-device-code-flow#use-it)), so this is hand-rolled with `URLSession`, about 120 lines including refresh; MSAL would be a CocoaPods/Carthage dependency and would not help here anyway.
- *Authorization code + PKCE with a loopback redirect*: register `http://localhost` under "Mobile and desktop applications" ([Desktop app configuration](https://learn.microsoft.com/entra/identity-platform/scenario-desktop-app-configuration)); open the browser at `/oauth2/v2.0/authorize` with `code_challenge`; receive the `code` on a one-shot listener (Deckhand's `MonitorServer` could serve `/auth/callback`, since `http://localhost` matches any port); exchange it with `code_verifier`. Nicer UX (one click, no code to type), a bit more code. MSAL for macOS would instead want `msauth.<bundle id>://auth` and the `com.microsoft.identity.universalstorage` keychain group ([MSAL redirect URIs](https://learn.microsoft.com/entra/msal/objc/redirect-uris-ios)).

Recommendation: device code. It matches the "sign in button with the device code shown" settings design the user asked for, needs no listener and no URL scheme, and the sign-in happens once. Use the **tenant-specific authority** (`https://login.microsoftonline.com/<tenant id or denoronha domain>/`) because the registration below is single-tenant.

**Token storage.** Access tokens live about an hour; the refresh token is exchanged at `/token` with `grant_type=refresh_token` and comes back rotated. Store `refresh_token` (and the cached `access_token` with its expiry) with `Store.shared.saveSecret(_, name: "msgraph")`, the user-only 0600 file Deckhand already uses for the pairing tokens and the Linear key (`Sources/UltraBarKit/Store.swift`, `AppModel.linearKey`), so no Keychain entitlement is needed. Sign out = delete the file. A refresh token for a public client stops working after 90 days without use or when the tenant revokes it; on `invalid_grant` Deckhand shows "Sign in again" on the page and in settings.

**Consent.** `Presence.Read` and `Presence.ReadWrite` are delegated permissions that a user can normally consent to themselves, and they are **not** in the list of permissions the Microsoft-managed default user consent policy blocks for end users (that list has Mail.*, Calendars.*, Chat.*, OnlineMeetings.* and others; see [Manage app consent policies](https://learn.microsoft.com/entra/identity/enterprise-apps/manage-app-consent-policies#microsoft-recommended-current-settings)). Because tier 1 takes calendar and mail from the Mac, the Graph scope list shrinks to presence plus `User.Read`, which also means no mailbox data ever leaves through Deckhand's registration. In the user's own tenant they are the admin anyway and can press "Grant admin consent" once.

### Not possible on macOS now

- **Mute, camera on/off, raise hand, leave, reactions, blur during a Teams call.** The only mechanism was the Teams desktop client's third-party app API; Microsoft retired it on 30 June 2026 for Windows and Mac (MC1266901). Graph's `communications/calls/.../mute` endpoints are for calls that a bot/application itself hosts (application permissions), not for the user's Teams client call. The Azure Communication Services calling SDK can mute and raise hands, but only inside a custom calling client, not the Teams app. There is no AppleScript dictionary for Teams and keystroke injection (Cmd+Shift+M for mute in Teams) only works while the meeting window is frontmost, which is unreliable and should not be shipped. What remains is the **passive** signal: presence `InACall`/`InAMeeting`/`Presenting` from Graph, and a "Leave" that is really just focusing Teams.
- **Unread Teams chat count, sending chat messages.** Possible with Graph `Chat.Read` / `ChannelMessage.Send`, but those scopes are admin-consent-only under the default policy and are out of scope for a presence-and-meetings page; leave them out.
- **Presence without any Microsoft sign-in.** No local source exists (Teams on macOS exposes nothing readable). Reusing a first-party Microsoft client id (Graph Explorer, Azure CLI) to skip the registration works technically but is against the terms and brittle; do the registration.
- **Presence for a personal Microsoft account.** Graph presence is "Not supported" for personal accounts; the registration below is for the De Noronha Consulting work tenant.

## 3. Registering the app in the De Noronha Consulting tenant (exact steps)

Sign in to the [Microsoft Entra admin center](https://entra.microsoft.com) with the De Noronha Consulting admin account (Global Administrator, Application Administrator or Cloud Application Administrator), then:

1. **Identity → Applications → App registrations → + New registration.** Name: `Deckhand`. Supported account types: **Accounts in this organizational directory only (De Noronha Consulting only – Single tenant)**. Redirect URI: leave empty for the device code flow (or choose platform *Public client/native (mobile & desktop)* and enter `http://localhost` if the PKCE variant is wanted later). Register.
2. On **Overview** copy **Application (client) ID** and **Directory (tenant) ID**. These are the only two values Deckhand stores in `settings.json`; neither is secret.
3. **Manage → Authentication.** If no redirect URI was added, *Add a platform → Mobile and desktop applications* is optional; scroll to **Advanced settings → Allow public client flows → Yes** (required for device code), Save. This is the step Microsoft's [public client guidance](https://learn.microsoft.com/entra/identity-platform/msal-client-applications#when-should-you-enable-a-public-client-flow-in-your-app-registration) calls for; it is also what distinguishes the app from a confidential client.
4. **Manage → API permissions → + Add a permission → Microsoft Graph → Delegated permissions.** Tick `Presence.Read` and `Presence.ReadWrite` (under *Presence*) and keep the default `User.Read`. Add. `offline_access`, `openid` and `profile` are requested in the scope string at sign-in and need no entry here (adding `offline_access` under *OpenId permissions* is harmless if the portal insists). Do **not** add Mail.* or Calendars.*: tier 1 reads those from the Mac.
5. Press **Grant admin consent for De Noronha Consulting** → Yes. Not strictly needed for presence scopes (users can consent themselves) but it removes the consent screen from the device-code sign-in and documents the grant under *Enterprise applications → Deckhand → Permissions*.
6. **Certificates & secrets: add nothing.** A public client has no client secret; a secret in a macOS app bundle would be extractable anyway. If someone later adds one, the device code and PKCE flows still work without it.
7. Optional hardening: *Enterprise applications → Deckhand → Properties → Assignment required: Yes*, then assign only the user's own account; *Branding* to add the Deckhand icon shown on the Microsoft sign-in page.

What Deckhand stores: client id and tenant id in `settings.json` (as plain settings, with a default of empty so the Teams app shows "Enter the client id of your app registration" until filled), the refresh token in the 0600 secret file, and nothing else. If Deckhand is ever distributed to other people, each of them either registers their own single-tenant app (this document) or the developer registers one multi-tenant app once (Supported account types: *any organizational directory*) and ships its client id, which is what FlowKits does; multi-tenant apps should then go through [publisher verification](https://learn.microsoft.com/entra/identity-platform/publisher-verification-overview) so other tenants' consent policies accept them.

## 4. Proposed design: the "Teams" bar app

Package `nl.denoronha.deckhand.teams`, page `/teams`, data at `/teams/data.json`, same 1424×280 canvas shell as the other eleven pages (`BarPages.html`, dark `#1c2029`, ✕ in the corner, "Waiting for the Mac…" overlay, poll loop). Three columns, 20 px gutters, 16 px top and bottom margins, 248 px of card height, following the Flights page's layout maths.

**Left, 300 px: presence block (tier 2; shows "Sign in in Deckhand → Apps → Teams" when no token).** A 56 px dot in the Teams colours (Available `#6bb700`, Busy and In a call `#c4314b`, Do not disturb `#c4314b` with the white bar, Away and Be right back `#ffaa44`, Offline `#8b94a6`), the availability as a 26 px label ("Available", "In a meeting", "Do not disturb", "Presenting"…), the status message in 15 px grey below it if set, and "until 15:30" when a preferred presence with an expiry is active. Tap on the block cycles the preferred presence through Available → Busy → Do not disturb → Away → (Reset to automatic = `clearUserPreferredPresence`) → Available, posting `/teams/presence/<available|busy|dnd|away|auto>` with the `X-Deckhand: action` header, optimistic paint, then a re-poll after 1.5 s like `/tasks/done`. A small "1 h" chip in the corner toggles a focus timer: DND with `expirationDuration=PT1H` and a visible countdown. While Graph says `InACall`/`InAMeeting`/`Presenting` the block stops cycling on tap (Teams would override it anyway) and shows "In a call" with the meeting title from the calendar if one overlaps now.

**Middle, 600 px: next meeting (tier 1).** The first event from the Exchange calendars whose end is in the future: title in 28 px, "14:00–14:30 · Ramon de Noronha" in 16 px grey (organiser from `EKEvent.organizer?.name`, or "you" when `isOrganizer`), a countdown in 44 px that reads "in 12 min", "starts now" (blinking amber from 2 min before start to 5 min after) or "ends in 18 min" when running. On the right of the column a 160×64 **Join** button in Teams purple `#5b5fc7` when a join link was found; a tap posts `/teams/join/<event id>` and the Mac opens the `msteams://` form of the link (fallback `https://`), so the meeting opens in the Teams desktop app on the Mac, not on the bar. When no link is found the button becomes "Open in Calendar" (`ical://` with the event, or just `open -a Calendar`). Nothing today: "No more meetings today" with tomorrow's first meeting in grey.

**Right, 440 px: rest of today + mail (tier 1).** The upper 170 px lists up to four further meetings for today, one line each: time in 15 px grey, title clipped, a small purple dot when it has a join link, greyed when past. The bottom 60 px is the mail strip: an envelope glyph, "12 unread" in 24 px (or "Mail not open" / "Allow Deckhand to control Mail in System Settings → Privacy & Security → Automation" when the AppleScript fails), the account name in grey, and a tap posts `/teams/mail` which brings Mail to the front. If the unified inbox is used, the count covers all accounts; the setting below picks one.

**Feeds in `BarPages.startFeeds`.** `teamsCalendar` every 60 s from `CalendarSource` with the new fields (reuse the calendar task, just enrich `CalEvent` with `organizer`, `joinURL`, `eventID`, `isFree`); `teamsMail` every 60 s via `NSAppleScript` on a utility task, 30 s while the page is open (`lastHit` pattern); `teamsPresence` every 10 s while the page is open and every 60 s otherwise, skipped entirely without a token; the countdown is computed client-side from `start`/`end` so the page ticks every second without new requests.

**Settings in Deckhand → Apps → Teams** (next to the existing Tasks and Flights panels in `AppsView.swift`):

- Panel **Meetings and mail (no sign-in)**: a calendar picker limited to the Exchange source (default: all Exchange calendars, reusing the Calendar widget's `calendarIDs` chooser), a toggle *Skip "Free" and all-day events* (on), a *Mail account* popup listing `name of every account` from Mail plus "All accounts (unified inbox)", and a line showing the Calendar and Automation permission state with a *Request access* button (the existing `CalendarSource.requestAccess` plus one AppleScript call to trigger the Mail prompt).
- Panel **Teams presence (Microsoft sign-in)**: text fields *Application (client) ID* and *Directory (tenant) ID* with a footer that points to this document's section 3; a **Sign in** button that starts the device code flow and then shows "Go to microsoft.com/devicelogin and enter **ABCD-EFGH**" with a *Copy code* and an *Open* button (the code is also painted on the bar's presence block while it waits, so the sign-in can be read from the bar); once signed in, "Signed in as ramon@… · presence refreshed 3 s ago" and a **Sign out** button (deletes the secret file); a popup *Poll presence every* 5 / 10 / 15 / 30 s while the page is open; a popup *Focus timer length* 30 min / 1 h / 2 h.
- No settings for in-call controls, because there are none; the panel footer says so in one line so nobody looks for them.

**What this design does not do, by Graph's or the Mac's rules:** change the presence of other people (would need `Presence.ReadWrite.All`); mute or unmute, camera, hands, reactions (retired local API); show a meeting's join link that Exchange did not put in the event body; count unread mail that Apple Mail has not fetched yet; show presence for a personal Microsoft account; push presence changes instantly (10 s poll, no webhook without a server); set "Appear offline" and keep Teams usable (Graph's Offline/OffWork works but Teams then shows you offline to everyone, so leave it out of the cycle and behind the settings panel if at all).

## 5. Summary and effort

**What the plugin does:** FlowKits' Flow for Outlook & Teams is a Graph-only client: Teams presence display and one-tap status cycling plus a focus timer, next-meeting countdown with join, agenda browsing, unread mail counts and inbox monitors that open Outlook on the web, Teams chat counts and preset messages. It has no in-call controls; those were the official Microsoft plugin's domain via the Teams local API, which Microsoft retired on 30 June 2026 on Windows and Mac.

**What Deckhand can offer:** everything except in-call controls and chats. Next meeting, countdown, today's list, the Join button that opens Teams on the Mac, and the unread count come from Apple Calendar (EventKit) and Apple Mail (AppleScript) with no account, no token and no consent, on code paths Deckhand already has. Only presence (read and set) needs Microsoft Graph with two delegated scopes.

**What the user must do first:** nothing for tier 1 beyond granting Calendar access (already done for the Calendar app) and the one-time Automation prompt for Mail. For tier 2, register `Deckhand` in the De Noronha Consulting tenant as a single-tenant public client with "Allow public client flows: Yes" and delegated `Presence.Read` + `Presence.ReadWrite`, press Grant admin consent, and paste the client id and tenant id into Deckhand → Apps → Teams (section 3). Before building, export one Teams invite from Calendar.app as .ics to confirm which field carries the `meetup-join` link.

**Estimated effort:** tier 1 about 1.5–2 days (enrich `CalEvent` and `CalendarSource` with organiser, join URL and free/all-day flags; Mail AppleScript with permission and not-running handling; the `/teams` page with countdown, join and mail routes; the Apps panel; MANUAL and registry entries).
